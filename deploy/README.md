# Запуск на Ubuntu

Это подготовленная конфигурация; подключение к серверу и развёртывание ещё не выполнялись. Порядок инвентаризации и границы удаления определены в `docs/delivery/deployment.md`. Сначала установите принадлежность старых ресурсов и проверьте соседние сервисы. Не используйте глобальные prune или удаление общих каталогов и томов.

Нужны Docker Engine с Compose plugin, существующий или настроенный reverse proxy и действующий TLS для synergyhub.top. Переиспользуйте совместимую инфраструктуру. Рабочий каталог выбирается после инвентаризации; команды ниже выполняются из корня checkout проекта.

## Конфигурация

```sh
cp deploy/.env.example deploy/.env
chmod 600 deploy/.env
```

Заполните файл локальным редактором. Не выводите полный файл, `docker inspect` или развёрнутый `docker compose config` в отчёт и общие логи. Пароли и секреты должны быть случайными и различными. Для POSTGRES_PASSWORD удобно использовать случайную hex-строку: она безопасна в URL. Укажите тот же пароль в DATABASE_URL. При другом формате пароль в URL нужно percent-encode; исходный POSTGRES_PASSWORD остаётся без кодирования. DATABASE_URL внутри контейнера использует host `db`, порт `5432`, database/user `tournament`.

Обязательны JWT_SECRET и BOT_API_SECRET (различные секреты минимум по 32 байта), BOT_USERNAME, ADMIN_TG_IDS и PUBLIC_BASE_URL. Дата старта задаётся администратором в интерфейсе и хранится в БД; переменная TOURNAMENT_START_AT не нужна. LOCAL_DEMO=false и NODE_ENV=production задаются compose явно.

BOT_TOKEN берётся у BotFather. Его отсутствие позволяет подготовить и запустить сайт; бот включается отдельным профилем только после получения токена. Два администратора присылают владельцу свой ID через `/id`; внесите оба числовых ID через запятую в ADMIN_TG_IDS. Сама команда права не назначает.

## Сборка и запуск

```sh
docker compose --env-file deploy/.env -f deploy/compose.yml build
docker compose --env-file deploy/.env -f deploy/compose.yml up -d db app
curl --fail http://127.0.0.1:3000/health
```

Backend применяет штатные миграции при старте. Данные PostgreSQL находятся в постоянном томе postgres_data. Порт БД не публикуется; приложение доступно proxy на 127.0.0.1:3000. Проверьте, что этот порт свободен, прежде чем использовать шаблон. Переименование compose-проекта меняет имя тома: сохраняйте установленное имя при обновлениях.

После настройки токена:

```sh
docker compose --env-file deploy/.env -f deploy/compose.yml --profile telegram up -d bot
```

Бот использует long polling: допускается ровно один экземпляр на токен. При существующем webhook бот останавливается с понятной ошибкой и сам его не удаляет. Сначала установите владельца webhook, остановите старый процесс и явно согласуйте переключение режима. Конфликт getUpdates также требует остановки второго процесса.

`nginx.conf.example` — шаблон для существующего virtual host домена. Пути сертификата `/etc/letsencrypt/live/synergyhub.top/` являются стандартным предположением; проверьте реальные сертификат, ключ и механизм продления до установки. Нельзя заменять общий конфиг nginx целиком. Весь домен, включая /api/v1 и SPA, направляется на backend, который обслуживает сборку frontend.

```sh
sudo nginx -t
sudo systemctl reload nginx
curl --fail https://synergyhub.top/health
```

Проверьте DNS A/AAAA, действительность TLS и внешнее открытие страниц, прямое обновление URL, реальные регистрацию/вход через Telegram и доступ обоих администраторов. Локальный health не подтверждает внешнюю доступность. До получения BOT_TOKEN реальная Telegram-проверка остаётся невыполненной.

## Обновление и диагностика

Сначала зафиксируйте версию приложения и сохраните резервную копию новой БД по эксплуатационной политике владельца. Обновите checkout, соберите образ и повторите запуск с тем же compose-проектом:

```sh
docker compose --env-file deploy/.env -f deploy/compose.yml build
docker compose --env-file deploy/.env -f deploy/compose.yml --profile telegram up -d
docker compose --env-file deploy/.env -f deploy/compose.yml ps
docker compose --env-file deploy/.env -f deploy/compose.yml logs --tail 100 app bot
```

Если Telegram ещё не настроен, обновляйте только `db app` без профиля. Не запускайте `down -v`: эта команда удаляет постоянную БД. Изменение POSTGRES_PASSWORD в env не меняет пароль уже созданной роли PostgreSQL; выполняйте согласованную ротацию роли и DATABASE_URL.

Для проверки сохранности данных перезапустите app и повторно откройте уже созданный профиль. Проверку перезагрузки сервера выполняйте после оценки соседних нагрузок; restart unless-stopped восстанавливает контейнеры при работающем Docker daemon. Не объявляйте автозапуск, TLS, Telegram и данные проверенными без фактических результатов.

Откат версии приложения зависит от совместимости миграций и резервной копии новой БД. Восстановление удалённых ресурсов прежнего проекта без резервной копии не предусмотрено.
