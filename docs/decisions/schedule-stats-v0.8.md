# Уточнение 0.8 — расписание и публичные показатели

Поручение владельца: четыре даты со временем в админке и заметные показатели на публичной главной. Только локальная разработка.

## Расписание

В `tournament_settings` добавляются nullable TIMESTAMPTZ `registration_start_at`, `registration_end_at`, `end_at`. `start_at` остаётся стартом турнира. При миграции новые значения null, существующий start_at сохраняется. Все даты API — UTC ISO. Последующее поручение [1.1](utc-admin-v1.1.md) устанавливает UTC также для ввода и отображения, заменяя прежнее местное время браузера.

GET `/public/tournament`, GET/POST `/admin/tournament/settings`: `{registration_start_at,registration_end_at,start_at,end_at,registration_open,registration_status,started,ended,server_time}`. POST принимает непустой частичный объект только из четырёх полей дат, объединяет с сохранёнными настройками в транзакции под блокировкой. Значения — ISO UTC либо null. Ответ — полное состояние.

`started = start_at != null && now >= start_at`; `ended = end_at != null && now >= end_at`. Регистрация по умолчанию открыта: `registration_open = (registration_start_at == null || now >= registration_start_at) && (registration_end_at == null || now < registration_end_at) && !ended`. Статус `UPCOMING` до начала регистрации, `CLOSED` после конца регистрации или турнира, иначе `OPEN`. Конец интервала исключительный. Если обе даты пары заданы, начало строго раньше конца. Само по себе начало турнира не закрывает регистрацию: за это отвечает дата конца регистрации. Конец турнира требует заданного start_at. При наличии end_at регистрационное начало не может быть >= end_at, регистрационный конец не может быть > end_at.

Любую уже наступившую сохранённую границу нельзя менять/очищать обычным действием (409 `SCHEDULE_DATE_LOCKED`; для start_at сохранить совместимый `TOURNAMENT_ALREADY_STARTED`). Будущие границы и null редактируемы. Новый/изменённый start_at только в будущем, как прежде. Прочие даты допускают прошлое для немедленного начала/закрытия; после сохранения становятся неизменяемыми по указанному правилу. Неверный порядок — 422 `VALIDATION_ERROR`. Блокировка смены существующего кошелька по start_at сохраняется навсегда, окончание турнира её не снимает.

Проверять окно при создании регистрационного pending и непосредственно при создании нового users через код либо deep link, в той же транзакции с блокировкой настройки; ошибка 409 `REGISTRATION_NOT_OPEN`. Существующий пользователь может входить через код/deep link независимо от окна, включая ранее выданный регистрационный токен. Получение кода в боте разрешено: оно само не создаёт участника. Действующие сессии, обновление профиля, проверка администратором не ограничиваются расписанием.

## Публичные показатели

GET `/public/stats` без авторизации возвращает `{participant_count:integer,initial_capital:decimal|null,current_capital:decimal|null,pnl:decimal|null,lp_volume:decimal|null,scored_participant_count:integer,capital_participant_count:integer,lp_participant_count:integer,server_time:ISO}`.

Выборка — допущенные APPROVED_AUTO/APPROVED_MANUAL с VALID кошельком, совпадает с допуском лидерборда. participant_count учитывает также участников без scoring. Суммы только загруженных ненулевых полей; SQL NUMERIC SUM, API decimal strings, при отсутствии данных null (не выдуманный ноль). scored_participant_count — количество ненулевых PNL, capital_participant_count — ненулевых current_capital, lp_participant_count — ненулевых lp_volume. Неполное покрытие явно указывается на карточках. UID/ROI не меняют эти суммы. Существующая демонстрационная запись участвует, как в лидерборде; не генерировать новые результаты или участников.

Отдельный nullable NUMERIC(20,6) >= 0 `tournament_scoring.lp_volume`: накопленный оборот открытий LP в SOL, вручную посчитанный и загружаемый администратором по каждому участнику. Владелец уточнил: 100 открытий по 0,5 SOL дают 50 SOL оборота, независимо от роста капитала с 1 до 2 SOL. Повторные размещения того же капитала учитываются; закрытия не удваивают оборот. Не является текущей суммой `in_positions_amount`, не вычисляется из капитала. Добавить поле в импорт результатов, его CSV-шаблон, админский просмотр и профиль scoring; публичный leaderboard контракт расширять не требуется. Старый импорт без lp_volume сохраняет прежнее значение; явный null очищает. Устаревшие суммы не дополнять случайными демозначениями.

Главная: четыре крупные карточки «Участников в турнире», «Капитал в турнире» (current_capital), «Общий PNL», «Оборот LP» (SOL), с точными суммами и заметным CTA в лидерборд. PNL с явным знаком, отрицательный не оформлять как прибыль. Подпись о загрузке результатов администратором; не заявлять доходность/ROI или неподтверждённые рекорды. Валюта существующих капитала и PNL не зафиксирована: не менять их единицы; SOL показывать только у нового оборота LP. Показывать данные и даты гостям; вход существующих участников остаётся доступен при закрытой регистрации. На узком экране карточки и поля адаптируются без горизонтального скролла.

## Проверка

Уточнение публичного оформления: «Показатели в турнире», «Участников в турнире», «Капитал в турнире». Над показателями на главной и других публичных экранах показывать компактные сроки: до закрытия регистрации — «Регистрация до …», «Начало турнира …», «Окончание турнира …»; после закрытия регистрации — только начало и окончание; после старта — только «Турнир до …»; после окончания — «Турнир завершён». Если дата не задана, явно писать «не назначено» без придуманной даты. Переходы используют серверное состояние и обновляются автоматически на границах. В админке полный редактор четырёх дат сохраняется.

Дополнительное поручение: на главной публичной странице и главной ЛК показывать баннер-заглушку с явной пометкой «ДЕМО»: «Special gift при поддержке партнёров: техника Apple на XXX $ и суперприз — будет раскрыт за 3 дня до окончания турнира». XXX остаётся незаданной суммой, это не подтверждённый призовой фонд. Никакой новой логики выбора награды участником, автоматического объявления или выдуманных партнёров. Если дата конца не задана, оставлять относительный срок, не выдумывать дату раскрытия.

Дополнительное поручение владельца: те же четыре общие карточки public/stats показывать над таблицей публичного лидерборда, гостям и авторизованным пользователям. Обновление лидерборда обновляет также агрегаты; индивидуальные столбцы таблицы сохраняются.

Тесты только в отдельных временных БД: границы расписания, новые/существующие участники через оба способа входа, сохранение блокировки кошелька, ограничения порядка и запрет изменения наступивших дат; точные суммы, отрицательный PNL, null/неполные данные, исключение недопущенных/невалидных, сохранение lp_volume старым импортом. Проверить админку с четырьмя полями и публичную главную на широком и узком экране. Реальные настройки/профили не менять во время проверки.
