# Доступ и уведомления — уточнение 0.6

Утверждено владельцем 08.10.2026. Дополняет контракт 0.5. Срок 24 часа и ограничение автоматической отправки раз в минуту ниже отражают версию 0.6 и заменены [контрактом 0.7](session-v0.7.md): 30 минут, подтверждение продления и общий лимит выдачи кода 90 секунд.

## Сохранение входа

- Подтверждённый JWT сохраняется для того же origin между переходами в лидерборд, перезагрузками и вкладками. Действующий JWT открывает кабинет без повторного запроса Telegram-кода.
- Срок входа определяется серверным JWT `exp`; текущая настройка — 86400 секунд (24 часа), минимально разрешённая настройка — 900 секунд (15 минут). Срок кода (5 минут) и ожидающей сессии (15 минут) не сокращает срок входа.
- Выход удаляет сохранённый JWT и ожидающее подтверждение, синхронизируется между вкладками. Истёкший JWT или серверный 401 требует нового входа. Ошибка сети, 403 на административный API и переход в публичную таблицу не завершают вход.
- При восстановленном действующем входе старое ожидающее подтверждение не открывается. JWT проверяет сервер, чтение `exp` браузером не является проверкой подписи.

## Автоматический код

После создания сессии сайта фронтенд вызывает `POST /api/v1/auth/code/request`:

```json
{"token":"auth_<суффикс>","telegram_identifier":"@username или числовой ID"}
```

- Входные поля строгие; сессия должна существовать, быть неиспользованной и неистёкшей. Если в ней указан ожидаемый username, он должен совпадать с вводом.
- Получатель определяется исключительно по ранее подтверждённым данным `users.tg_id/tg_username`. Клиент не передаёт доверенный chat_id. Для неизвестного аккаунта автоматическая доставка невозможна: пользователь отправляет `/start` боту, получает код и подтверждает Telegram.
- Генерация, HMAC, срок 5 минут и лимит 5 попыток соответствуют 0.5. Код передаётся только в Telegram, никогда в публичный ответ API, журнал или браузерное хранилище. Используется общий транспорт Telegram, доступный для подстановки в изолированных тестах.
- Не более одного автоматического запроса на Telegram ID в минуту; дополнительно лимит API по IP. Обычный `/start` позволяет получить новый код. Повторный автоматический запрос в течение минуты не инвалидирует уже доставленный код.
- Для валидной сессии одинаковый ответ `200 {"status":"requested"}` независимо от известности аккаунта и результата доставки; он не обещает успешную доставку и не раскрывает наличие аккаунта. Telegram 403, неизвестный получатель и временная ошибка не ломают ручной `/start`. Ошибки транспорта не содержат секретов.
- Интерфейс сообщает: если бот уже запущен, код придёт автоматически; если кода нет, открыть `@lptournamentsupport_bot` и нажать Start / отправить `/start`. Длинную команду переносить между устройствами не требуется.

## Допуск внешнего участника

- `PENDING_VALIDATION`: «Вы пока не допущены к турниру. Обратитесь к администратору для проверки и допуска. Профиль можно заполнить сейчас».
- `REJECTED`: «Допуск к турниру отклонён. Обратитесь к администратору для уточнения».
- В кабинете для этих статусов доступны контакты `@LeoCryptus` и `@D_mOnII` со ссылками Telegram. Подтверждение Telegram само по себе не означает допуск к турниру.
- При новой регистрации участник получает своё уведомление о статусе; внешнему участнику сообщение содержит отсутствие допуска и контакты администратора. Административные уведомления о новой регистрации сохраняются.
- При изменении статуса участник получает соответствующее уведомление. Никаких изменений таблиц или статусов допуска не требуется.
- Административный список показывает display_name, username и числовой Telegram ID в явных полях. Поиск принимает username с `@` и без него. Список перечитывается при переходе в админку и по кнопке обновления; регистрация в другом браузере не должна требовать повторного входа администратора.

## Проверка

Изолированная БД: код доставляется автоматически ранее подтверждённому аккаунту; неизвестный аккаунт получает нейтральный ответ; отказ доставки допускает `/start`; повторный запрос не заменяет код в минуту; код не выдаётся публично. Браузер: внешний участник видит контакты; вход сохраняется после таблицы, обновления и новой вкладки, действует спустя 15 минут; выход очищает все вкладки.
