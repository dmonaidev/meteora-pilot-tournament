# Уточнение1.1 — время UTC и отклик разделов админки

Поручение08.10.2026: вся платформа использует UTC для ввода/отображения времени; в редакторе удобные календарь и часы. При выборе плитки админки нижняя область немедленно соответствует выбранному разделу, старые базы/редакторы не остаются видимыми.

## Время

Поправка владельца08.10.2026 после просмотра английского native time input: формат ввода всегда24часа без AM/PM. Поле времени отображает ЧЧ:ММ (либо ЧЧ:ММ:СС при ненулевых сохранённых секундах), под полем явно «24 часа · UTC». Кнопка часов открывает собственную компактную панель выбора часов00–23 и минут00–59 с «Готово», чтобы локаль системы не возвращала12часовой формат. Календарь остаётся нативным. Существующие абсолютные даты, секунды/точность неизменённых значений сохраняются. Публичное форматирование явно использует hourCycle:h23 вместе с UTC. Это уточнение заменяет требование нативного picker для времени в следующем абзаце.

API/БД остаются прежними: ISO UTC с Z/TIMESTAMPTZ, абсолютные моменты времени не сдвигать и не переписывать. Дополнение заменяет прежнее отображение в местном часовом поясе браузера из0.8.

Расписание вводится отдельными date и time с шагом1сек, в UTC, с заметными кнопками Calendar/Clock, открывающими соответствующий нативный picker. Метки доступности: «Начало регистрации · дата», «Начало регистрации · время (UTC)» и аналогичные остальные3пары. Для каждой границы оба поля пустые означают null; одно пустое — незавершённый ввод с ошибкой до POST. Оба заполнены — составить date + T + time + Z, строго проверить календарную дату без автопереноса invalid day. Чтение ISO заполняет UTC-компоненты; timezone браузера и DST не участвуют. Наступившие границы и условия backend неизменны. Очистка удаляет пару целиком. UTC явно подписан возле редактора и публичных дат.

Публичные сроки/расписание, административные таблицы дат используют timeZone:'UTC'. Числовые countdown/истечения сессии остаются длительностями, не календарными датами. Не переводить пользовательские значения обратно из local zone.

## Переключение разделов

Авторизованный пункт меню «Главная» переименовать в «Личный кабинет»: он открывает profile view, свои данные и статусы. Новый публичный экран не добавлять; ранее утверждённые показатели/баннер в ЛК сохраняются. Гостевая публичная страница и лидерборд остаются прежними.

Плитки — type=button, явный aria-pressed. Выбор синхронно меняет выбранный ID; содержимое имеет data-section и key этого ID. Разделы/формы не делят состояния данных. При загрузке показывать loader текущего раздела вместо старых строк/чужого редактора. Отменять предыдущие GET на уходе/смене параметров, игнорировать запоздавшие ответы/ошибки. Обновление данных/сессии не меняет выбранную плитку. Кнопки выбора не блокируются ожиданием сети другой секции. Если старый запрос завершил операцию записи, её серверный результат сохраняется, но не возвращает старый экран.

## Проверки

Изолированный браузер в timezone America/Los_Angeles: ввод2030-05-10 12:00 отправляет2030-05-10T12:00:00.000Z и после refresh остаётся12:00, публичный текст тожеUTC. Неполная пара не пишет настройки. Проверить иконки/доступность picker, mobile390px. Задержать запросы таблиц и настройки, быстро переключить несколько плиток, отпустить старые ответы; activeплитка, заголовок, data-section, ресурс/редактор всегда согласованы. Реальное расписание и профили во время проверки не менять.
