# Уточнение 1.2 — квалификация Special Gift

Основание: согласованный предварительный макет и поправка владельца 08.10.2026. Во всех шагах вывода и подсказках используется **Ваш турнирный кошелёк**, а не «новый личный кошелёк». Название меню «Личный кабинет» не меняется.

## Ссылка партнёра

Администратор задаёт реферальную ссылку в разделе **Настройки турнира**, отдельной формой. Поле `tournament_settings.partner_referral_url`: nullable text, первоначально null. Новая миграция009 не меняет профили и даты. Строка обрезается по краям; пустая строка нормализуется в null. Непустая строка — абсолютная HTTPS URL до2048 символов, без credentials и управляющих символов. Не делать HTTP-запросов на введённый адрес.

Новые API:

- `GET /api/v1/public/partner` → `{ "referral_url": "https://…" | null }`, доступен гостю.
- `GET /api/v1/admin/tournament/partner` → тот же объект, только admin.
- `POST /api/v1/admin/tournament/partner` с `{ "referral_url": string | null }` → сохранённый объект. Строгая схема, отказ422 при недопустимом URL, 401/403 для отсутствия доступа. Отдельная транзакция обновляет только partner_referral_url: расписание и его блокировки не затрагиваются.

Ссылка **«Выполнить условия для прохождения квалификации»** под строкой о суперпризе в демобаннере имеет тот же размер шрифта. В ЛК над UID — «Хочу Special Gift от партнёра» и такая же ссылка. В дорожной карте шаг2 также ссылается на неё. Все три места используют одну настройку; внешний переход в новой вкладке с noopener noreferrer. Пока URL не задан, ссылку не подменять произвольным адресом: показать текст и короткое «Ссылка партнёра пока не опубликована». Сохранение формы админки обновляет видимые ссылки без нового входа. Ошибку загрузки не считать отсутствием ссылки.

## Дорожная карта и подсказка

Справа от профиля, под проверкой данных, компактная вертикальная дорожная карта:

1. Зарегистрироваться на турнир (подтверждение Telegram).
2. Создать новый аккаунт на бирже по ссылке партнёра.
3. Пополнить счёт от100 USDT.
4. Обменять USDT на SOL на споте; можно лимитным ордером.
5. Вывести SOL на Ваш турнирный кошелёк; сохранить хэш вывода.
6. Указать UID аккаунта биржи и хэш вывода, отправить на проверку.
7. Указать кошелёк для турнира; дождаться проверки администратора.

Шаги2–6 относятся к Special Gift, шаги1/7 — к участию в турнире вообще. Минимальный объём обмена числом не задан владельцем и не придумывается; администратор проверяет объёмы вручную. Без интеграции с биржей шаги2–5 не становятся выполненными от клика по ссылке, ввода UID или checkbox. UID UNDER_REVIEW показывает текущий шаг6 с кружком и ожиданием ручной проверки; VALID подтверждает шаги2–6 как единый результат ручной квалификации. Кошелёк считается подтверждённым только при wallet.validation_status=VALID. INVALID показывается как необходимость исправления, не как ожидание/успех.

При незаполненной квалификации отображается раскрываемая минипанель «Как участвовать в Special Gift?» с приглашением выполнить условия и побороться за ценные призы партнёра. Доступна по клику и клавиатуре, aria-expanded; закрытие не меняет ввод. Данные для дорожной карты и итогового статуса берутся из сохранённого профиля, несохранённый checkbox не меняет подтверждение/номинацию. Общий допуск к турниру остаётся отдельным существующим статусом.

## Короткий статус под приветствием

Номинация заявки определяется сохранёнными rewards.reward_type и exchange_uid. PARTNER_GIFTS с UID означает заявку Special Gift даже до проверки; отсутствие UID означает только Respect Gift. Не путать заявку с подтверждённым reward_tag лидерборда.

| Сохранённые данные | Краткая строка |
| --- | --- |
| Special Gift, UNDER_REVIEW | Special Gift · ожидает проверки партнёра |
| Special Gift, VALID | Special Gift · подтверждён партнёром |
| Special Gift, INVALID | Special Gift · квалификация не подтверждена |
| Только Respect Gift, допуск approved и кошелёк VALID | Respect Gift · допуск подтверждён |
| Только Respect Gift, остальные незавершённые проверки | Respect Gift · ожидает проверки |
| Только Respect Gift, отклонён допуск/кошелёк | Respect Gift · требуется уточнение |

VALID для UID администратор выставляет после ручной проверки свежей регистрации по ссылке, депозита, объёма спот-обмена и UID. В существующей форме проверки UID пояснить этот смысл и подписать подтверждение «Подтвердить UID и квалификацию». Нового автоматического доступа к партнёру/бирже или дополнительных фиктивных статусов нет. Прежние API uid_status, вывод награды, запрет смены кошелька после старта, PNL и условия регистрации сохраняются.

## Проверки

Тесты на отдельной БД: прав доступа и URL, сохранение/очистка ссылки без изменения дат, сохранение при повторном чтении; четыре основных строки и отклонения; состояние «на проверке» без ложных отметок шагов2–5; обновление ссылки в ЛК/баннере; мобильная компоновка. Рабочие профили и реальные уведомления при тестировании не менять. Деплой не выполняется.
