# Сессия 30 минут и подтверждение в боте — контракт 0.7

Поручение владельца от 08.10.2026. Этот документ заменяет срок 24 часа и ограничение 60 секунд из 0.6. Остальные сценарии допуска и данных сохранены. Работа только локальная.

## Поведение

- Подтверждённый вход действует 30 минут. За последние 5 минут сайт показывает баннер: «Сессия завершится через … . Подтвердите продолжение через бота, чтобы остаться в кабинете без повторного входа».
- Кнопка сайта «Продолжить через Telegram» отправляет в личный чат этого пользователя сообщение с inline-кнопкой «Подтвердить сессию на сайте» и текстом: «Подтвердите продолжение сессии на сайте. Если не подтвердить, после её завершения потребуется снова войти по коду».
- Кнопка подтверждения действует максимум 5 минут и только до текущего конца сессии. Нажатие именно владельцем Telegram до срока продлевает именно эту сессию на 30 минут от подтверждения. Сайт получает новый JWT через опрос; код и повторная регистрация не нужны.
- После истечения срока кнопки, окончания сессии или выхода подтверждение невозможно. Старые и повторно нажатые кнопки не продлевают сессию. Без ответа вход завершается и новый вход выполняется по коду. Простое нажатие кнопки сайта само не продлевает срок.
- Продление синхронизируется во вкладках с той же сессией. Оно не авторизует другие устройства или другой аккаунт. Обычная навигация, 403 и сетевые ошибки не завершают действующий вход.

## Состояние и JWT

Новая таблица `auth_sessions`: `id UUID PK`, `user_id UUID FK users`, `expires_at TIMESTAMPTZ`, `revoked_at TIMESTAMPTZ NULL`, `legacy_token_hash CHAR(64) NULL UNIQUE`, `renewal_token VARCHAR(43) NULL UNIQUE`, `renewal_expires_at TIMESTAMPTZ NULL`, `renewal_requested_at TIMESTAMPTZ NULL`, `renewal_message_id BIGINT NULL`. Точные ограничения миграции проверяет Backend Agent с оркестратором; дополнительные таблицы не нужны.

Новые JWT имеют sub=user_id, jti=auth_sessions.id, iat, exp, подпись HS256. Все приватные действия проверяют подпись и активное серверное состояние сессии. Новые login/code/verify и старый подтверждённый auth/session создают или используют одну серверную сессию; повторный polling не переносит её срок вперёд. Для связи website pending session допускается новый nullable `pending_sessions.auth_session_id UUID FK auth_sessions`.

Существующий JWT без jti принимается максимум до min(exp, iat+30 минут), однозначно связывается с серверной сессией по SHA256 самого токена. JWT без корректного iat не принимается. Перезагрузка сервера не сбрасывает ограничения. Действующая локальная настройка AUTH_JWT_TTL_SECONDS=1800; старые 24-часовые токены не сохраняют 24-часовой доступ.

## API

- `GET /api/v1/auth/access`: Bearer JWT. Ответ `{expires_at:ISO,server_time:ISO,access_token:string,token_type:'Bearer',renewal:null|{expires_at:ISO}}`. JWT имеет тот же серверный deadline, повторное чтение не продлевает сессию. Этот маршрут может принять ранее истёкший JWT **только** для получения уже подтверждённого продления той же активной серверной сессии; подпись, sub/jti (либо fingerprint legacy) и состояние обязательны. Обычные приватные API не получают такого исключения. Если подтверждение не было получено до конца, ответ 401.
- `POST /api/v1/auth/renew/request`: действующий Bearer; тело `{}`. Доступен только в последние 5 минут. Ответ `{status:'requested',expires_at:ISO,retry_after_seconds:integer}`. Deadline=min(now+5 минут, текущий expires_at). Не более одной отправки за 90 секунд на сессию; повтор в этом окне возвращает тот же запрос и remaining cooldown. При разрешённой повторной отправке прежняя кнопка заменяется. Вне окна — 409 RENEWAL_NOT_AVAILABLE. Ошибка доставки — 503 TELEGRAM_UNAVAILABLE, право входа не теряется.
- `POST /api/v1/bot/session/confirm`: X-Bot-Secret; тело `{token:43 URL-safe symbols,tg_id:positive safe integer}`. Только реальный callback_query.from.id, без доверия chat_id или username. Ответ `{status:'confirmed',expires_at:ISO}`. Неверный/истёкший/использованный — 410 RENEWAL_EXPIRED; чужой Telegram — 403 FORBIDDEN. Под блокировкой БД проверить deadline, владельца, отсутствие revoke; atomically обновить expires_at на now+1800 и очистить challenge.
- `POST /api/v1/auth/logout`: действующий Bearer; `{}`; ответ `{status:'logged_out'}`. Отзывает серверную сессию и challenge. Сайт очищает JWT/ожидающую авторизацию и синхронизирует вкладки.

Telegram callback_data: `sr_<renewal_token>` (46 байт, ниже лимита 64). Bot polls allowed_updates message+callback_query, отвечает answerCallbackQuery с результатом, удаляет inline-кнопку после успешного подтверждения либо истечения при нажатии. Telegram не поддерживает таймер самоудаления inline-кнопок: истечение обязательно на сервере. Фоновая проверка раз в 15 секунд удаляет клавиатуру истёкшего запроса по сохранённому renewal_message_id; после рестарта проверяет сохранённые истёкшие запросы. Даже при сбое Telegram кнопка не даёт права продлить вход после срока.

Общий createTelegramTransport принимает `{chat_id,text,reply_markup?}` и возвращает безопасный message_id при его наличии. Новый createTelegramEditor(config) принимает `{chat_id,message_id}` и удаляет клавиатуру (editMessageReplyMarkup, inline_keyboard=[]); config.editTransport заменяет его в тестах. OTP и уведомления продолжают использовать тот же транспорт. Секреты, JWT, challenge и коды не выводить в журнал или админские списки.

## Username и защита отправки

- Ввод trim; один ведущий @ удаляется, username сравнивается без учёта регистра. В БД username хранится без @, показ пользователю — с @. Telegram ID сохраняется числом и не преобразуется в username. Это правило одинаково для регистрации, входа, запроса/проверки кода и поиска в админке.
- Новый код одному Telegram ID выдаётся не чаще одного раза в 90 секунд, как с сайта, так и через /start либо /code. Ограничение проверяется на сервере под блокировкой по последней выдаче в pending_sessions и переживает рестарт. До срока повтор не инвалидирует уже выданный код.
- `/auth/code/request`: нейтральный `{status:'requested',retry_after_seconds:90}` независимо от наличия аккаунта и результата доставки. `/bot/code` при cooldown отвечает `429 {error:{code:'CODE_COOLDOWN',message:string,fields:[]},retry_after_seconds:remaining}`; бот поясняет время ожидания без выдачи нового кода. Сайт показывает кнопку «Отправить код повторно» с обратным отсчётом 90 секунд и сохраняет deadline при перезагрузке. IP-лимиты сохраняются.
- Срок кода остаётся 5 минут. Повтор по истечении 90 секунд выдаёт новый код и инвалидирует предыдущий. Смена username, @, регистра и новой website pending session не обходит ограничение Telegram ID.

## Приёмка

Изолированная БД/Telegram mocks: 30-минутный JWT; баннер в 25:00; кнопка сайта не продлевает срок; верный callback продлевает, чужой/повторный/просроченный/после logout не продлевает; гонки завершаются одним подтверждением. Подтверждение на границе и последующий polling после исходного exp получает новый JWT только при действующем серверном продлении. Без подтверждения на 30:00 — 401 и новый вход. Нормализация с/без @ даёт одного пользователя. Cooldown 89 секунд блокирует, 90 разрешает, переживает новый экземпляр app и ограничивает /start и сайт совместно.
