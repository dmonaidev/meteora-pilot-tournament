# Проверка локальной реализации 0.5

Дата: 8 октября 2026 года. Проверены дополнения [0.3](../decisions/current-contract-v0.3.md), [0.4](../decisions/admin-data-v0.4.md) и [0.5](../decisions/telegram-code-v0.5.md). Деплой не выполнялся.

## Выполнено

- Реальная Telegram-регистрация администратора 940001 завершена; приватный profile и admin/users отвечают 200.
- Ошибка Telegram 400 из-за локальной inline-кнопки подтверждена реальным API и исправлена: для локального сайта бот отвечает текстом. Очередь команд обработана, повторная постоянная ошибка ответа не блокирует следующие сообщения.
- Демо-вход выключен в активной конфигурации: accounts/login демо возвращают 404. Администраторы определяются только по двум утверждённым Telegram ID.
- В админке семь разделов. Реальные административные данные, поиск, пагинация и отсутствие горизонтального переполнения страницы проверены на ширинах 1440 и 390.
- Новый бот выдаёт шестизначный код по обычному /start. Реальная отправка сообщения с кодом администратору успешно принята Telegram API; содержимое кода в отчёт не записано.

## Автоматические проверки

npm test: 35 passed, 0 failed, 0 skipped. Тесты выполняются в отдельной временной PostgreSQL-базе; после завершения удаляется только база, созданная данным запуском. Проверены HMAC-хранение, ведущие нули, TTL, сохранение пяти неудачных попыток, инвалидирование старого кода, связь username/ID, гонки одноразового использования, ограничения запросов, приватность, атомарность импорта, блокировка даты и кошелька.

npm run test:browser: 2 passed. Браузерный набор использует отдельную временную БД и отдельный HTTP-сервер. Проверены:

1. Регистрация по коду → кошелёк без UID/хэша → вход администратора по коду → одобрение → импорт PNL → гостевой лидерборд.
2. Вход с числовым Telegram ID и без username → восстановление pending session после перезагрузки без сохранения кода → семь разделов админки → поиск/пагинация → сохранение и очистка даты с повторным чтением после перезагрузки.

Набор application.spec.mjs заменяет прежние активные браузерные проверки через демо-переключатель. Старый browser.spec.mjs оставлен как историческая проверка деморежима и не запускается текущей конфигурацией Playwright.

## Практические пределы проверки

Успешный sendMessage подтверждает принятие сообщения Telegram, а не факт его чтения человеком. Для пользовательской проверки на телефоне отправить /start в @lptournamentsupport_bot и ввести полученный код на сайте. Срок кода 5 минут; новый /start заменяет прежний код. Текущий локальный сайт работает на компьютере владельца; Telegram на телефоне не должен открывать локальную ссылку.
