# Проверка локальной версии 0.8

08.10.2026. Расписание, публичные суммы и баннер по [контракту 0.8](../decisions/schedule-stats-v0.8.md).

- `npm run build` — успешно.
- `npm test` — 60/60, ошибок/пропусков нет; отдельная временная PostgreSQL БД. Четыре новых сценария проверяют границы дат, неизменяемость, гонку закрытия регистрации, новые/существующие входы, кошелёк после конца, точные суммы/покрытие, сохранение отсутствующего LP и очистку явным null.
- `npm run test:browser` — 5/5. Проверены четыре даты и сохранение после reload, запрет новой регистрации до её начала с доступным обычным входом, импорт оборота 50 SOL и публичные суммы, баннер ДЕМО, мобильные разделы, сессия 30 минут/Telegram-продление/cooldown90. Проверки изменений только в отдельной временной БД, сообщения Telegram подменены.
- Текущий localhost: /health 200, три пользователя сохранены. Четыре реальные даты остаются null; регистрация открыта. Публичные показатели соответствуют единственной допущенной записи с VALID кошельком: current_capital 1250.000000, pnl 250.000000, lp_volume null. Это ранее заданная демонстрационная запись; оборот LP не выдумывался.
- Главная и лидерборд содержат четыре общие карточки. Баннер Special gift явно отмечен ДЕМО, техника Apple на XXX $, суперприз за три дня до конца. Широкий и мобильный экраны проверены визуально; горизонтального переполнения, ошибок страницы и API-контракта не обнаружено.
- Последующая правка формулировок «в турнире» и компактных сроков проверена отдельным браузерным сценарием: автоматические переходы трёх сроков → двух → «Турнир до» → завершение прошли без перезагрузки. Локальная проверка после сборки повторена: три пользователя и null даты сохранены, четыре поля админки, /health200, ошибок страницы и мобильного переполнения нет. Пять предыдущих сценариев здесь не прогонялись повторно после этой правки оформления.
- Локальные приложение и бот перезапущены, миграция006 применена. Сервер и DNS не затрагивались. Секреты не менялись и не публиковались.
- Последующее поведение UID проверено расширенным сценарием регистрации в отдельной браузерной БД: первый профиль начинает с включённым UID, пустые UID/хэш блокируют сохранение, явное отключение показывает отказ от Special Gift, сохраняет null UID/хэш и после reload остаётся отключённым. Сценарий прошёл вместе с последующей модерацией, импортом результатов и гостевым лидербордом.
- Последующее оформление: мелкие explicit7–14px увеличены на50% одним проходом, крупные значения/заголовки сохранены. Изолированный сценарий регистрации из этой кнопки, UID, модерации и результатов прошёл.
