# Один прогон согласованности спецификации

Дата: 8 октября 2026 года. Результат: ревизия 0.2.1.

## Что проверено

Сопоставлены Agent.md, план детализации, 12 сценариев, словарь полей, шесть таблиц, API, 11 алгоритмов, интерфейсы, решения и критерии приёмки. Сводная [модель продукта](../architecture/product-model.md) связывает их в один поток.

Проверка выполнялась по текущим правилам владельца: ручная загрузка PNL, необязательный ROI, адрес с хэшем вывода без signature, блокировка смены адреса с момента T. Исторический source/model-v3.txt сохранён без изменения и не проверялся как действующий контракт.

## Исполненный логический прогон

В памяти исполнена модель правил с проверкой ожидаемых результатов. Это проверка формализации документации, не тест реализации приложения.

| Набор | Объём | Результат |
| --- | --- | --- |
| Регистрация × кошелёк × награда × score | 4 × 4 × 5 × 4 = 320 сочетаний | Допуск, видимость приватного score и reward_tag совпали с правилами |
| Подача кошелька | 30 переходов: три момента T−1/T/T+1, первая подача и повторы/смена хэша/адреса при трёх статусах | Граница now >= T и сброс проверки согласованы |
| Срок сессии | 6 случаев: is_used false/true × 899/900/901 секунд | В 900 секунд обе сессии истекли |
| Числовая сортировка | 7 строк: null, отрицательный PNL, 2, равные 10, две большие суммы с разницей 0.000001 | Порядок точный, равенство по id, ROI игнорируется |
| Сквозной путь | Регистрация → данные → допуск → PNL → UID → запрет смены → закрытое исключение → восстановление → отзыв/возврат допуска | Сохранённый PNL не потерян |

Всего в этом исполнении: 1044 проверки условий, 0 нарушений. Подсчёт включает несколько условий для одного состояния и не означает 1044 независимых продуктовых сценария. Числовая сортировка проверялась через целое число миллионных долей (BigInt), без потери точности float.

Пример сквозного пути: участник вне initial_users получает PENDING_VALIDATION. После подачи пары и выбора PARTNER_GIFTS остаётся вне списка. Одобрение регистрации и кошелька включает его с null-метриками. Загрузка pnl=100.000000 показывает результат; одобрение UID меняет только метку. В момент T обычная смена адреса запрещена. Закрытое исключение сохраняет PNL, но скрывает участника до VALID новой пары. Отзыв регистрации скрывает его из публичного списка; собственный score при VALID wallet остаётся видимым. Восстановление регистрации возвращает прежний результат.

## Проверка структуры комплекта

- 22 JSON-примера разобраны JSON-парсером.
- Идентификаторы SC-01–12, ALG-01–11, AC-01–73 последовательны и не повторяются.
- При финальном чтении 14 действующих файлов проверены 25 внутренних Markdown-ссылок: отсутствующих целей нет; сохранённый текст совпал с подготовленными изменениями.
- Новые таблицы, endpoint для обхода блокировки и автоматические источники финансовых данных не добавлены.
- Изменения сведены в RFC-06; версия действующих документов — 0.2.1.

## Вывод и границы

В проверенной области после исправлений противоречий не обнаружено. Документы описывают один согласованный продукт и подходят как основание для реализации по DEV-01–09.

Транзакции PostgreSQL, реальные конкурентные запросы, Telegram, JWT, форматные валидаторы и UI этим прогоном не исполнялись. В частности, AC-71/72 фиксируют требования к будущим тестам конкурентного импорта, а не результат уже выполненного теста БД. Программная приёмка всех AC остаётся этапом разработки.

Перед запуском нужно подставить фактические параметры турнира, бота и авторизации. Они не выводятся из демонстрационных данных этого прогона.
