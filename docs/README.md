Версия 0.2.1. Назначение продукта: зарегистрировать пользователя, проверить допуск к турниру и показать его результат в лидерборде. Готовый PNL загружает администратор; leaderboard сортируется по PNL по убыванию. ROI загружается по желанию и остаётся справочным. Автоматический сбор балансов, котировки и анализ блокчейна в объём этой разработки не входят.

Основание: исходная модель версии 3.0, [Agent.md](../Agent.md) и уточнение владельца о загрузке скоринга администратором. Исходный текст сохранён в [model-v3.txt](source/model-v3.txt). Это описание исходной версии 0.2.1; последующие утверждённые дополнения выше добавляют таблицы настроек, сессий и версий правил. Wallet challenge не реализован. В существующие wallets и tournament_scoring добавлены withdrawal_tx_hash и pnl по утверждённым решениям.

## Объём продукта

1. Регистрация с display_name, согласием с опубликованной редакцией правил и подтверждением через Telegram.
2. Повторный вход через Telegram.
3. Автоматический допуск по initial_users либо ручное решение администратора.
4. Форма ЛК с адресом, условными UID/хэшем и состояниями проверок; награда определяется сервером.
5. Ручная проверка пары адрес/хэш и UID администратором, без криптографического доказательства владения.
6. Загрузка администратором готового pnl и необязательных справочных метрик в tournament_scoring.
7. Публичный лидерборд с фильтром допуска, pnl DESC и reward_tag.
8. Запрет обычной смены существующего адреса после TOURNAMENT_START_AT. Исключительный перенос администратором остаётся закрытой операцией.

Один сервер приложения, одна PostgreSQL, общий API для сайта и бота. Бот передаёт подтверждённый Telegram ID; все записи делает сервер. Продукт использует девять таблиц: шесть исходных, tournament_settings, auth_sessions и tournament_rules.

## Статус передачи

Прежние вопросы о результате, сортировке, подписи и смене адреса закрыты решениями владельца. Действующий контракт — исходная версия 0.2.1 с обязательными дополнениями 0.3–1.3 выше. Он имеет приоритет над историческим source/model-v3.txt, где ROI ещё назван автоматическим и указан signature. Исходный архив сохранён для происхождения требований и не используется как альтернативная спецификация.

Параметры бота/авторизации задаются в окружении. Расписание задаётся администратором в БД через админку; новая регистрация требует публикации правил. Это обязательные значения конфигурации, не новые функции. Комплект документации можно передавать разработчику; реализация и программные проверки выполняются по delivery/acceptance.md.
