# Интерфейсы и права криптотурнира

Актуальные экраны, поля и права описаны в [единой спецификации доступа и ЛК 0.8](access-and-cabinet.md); публичная главная и четыре даты админки — в [дополнении 0.8](../decisions/schedule-stats-v0.8.md). Описание версии 0.2.1 ниже является исходной моделью.

Версия 0.2.1. Каждый экран использует данные API. Сайт не назначает допуск и не вычисляет reward_tag самостоятельно.

## Лендинг

Кнопки «Регистрация» и «Вход», ссылка на leaderboard. Регистрация открывает поле display_name с длиной 3–20 после trim. После отправки кнопка блокируется до ответа, чтобы не создавать pending sessions повторным кликом.

Успех register/login показывает bot_link и ожидание подтверждения. Polling раз в 3 секунды. При истечении предлагается начать заново; при успехе окно закрывается и открывается ЛК. Закрытие окна останавливает polling.

## Личный кабинет

| Состояние | Что показать | Что разрешить |
| --- | --- | --- |
| APPROVED_AUTO / APPROVED_MANUAL | Регистрация одобрена | Заполнение wallet и rewards |
| PENDING_VALIDATION | Аккаунт не найден в списке, ожидает проверки | Заполнение wallet и rewards |
| REJECTED | Допуск отклонён | Заполнение wallet и rewards по исходному правилу |
| wallet=null | Поля адреса и хэша вывода с биржи | Первая отправка обоих значений, подпись не нужна |
| wallet UNDER_REVIEW | Адрес, хэш и ожидание проверки | Повтор пары; адрес менять только при wallet_address_locked=false |
| wallet INVALID | Адрес, хэш, причина rejection_reason | Исправление хэша и повтор; адрес после старта заблокирован |
| wallet VALID | Адрес, хэш и подтверждение | Блок scoring; смена адреса только до старта; новый хэш → повторная проверка |
| rewards=null | Выбор RESPECT / PARTNER_GIFTS | Сохранение выбора |
| RESPECT | UID не требуется | UID скрыть и передавать null |
| PARTNER_GIFTS | UID и uid_status | Первая подача или изменение UID |
| scoring=null при VALID wallet | Данные ещё не загружены администратором | Только просмотр |
| scoring object при VALID wallet | PNL как основной результат; capital-поля и ROI при наличии как справочные | Только просмотр |

В форме данных регистрации/ЛК расположить wallet_address и обязательный withdrawal_tx_hash рядом с существующим блоком выбора наград/UID. exchange_uid подписать «UID аккаунта на бирже», не «UUID». Адрес и хэш сохраняются вместе через user/wallet; reward_type/UID — через user/rewards.

wallet_address_locked вычисляется сервером по TOURNAMENT_START_AT. Значение true делает существующее поле адреса readonly для любого статуса wallet. Показывать «Кошелёк закреплён на турнир». Не показывать кнопку исключительной смены и не обещать перенос прогресса. Хэш остаётся доступен для исправления с новой ручной проверкой. Если форма открыта до старта и сервер вернул WALLET_CHANGE_LOCKED, перечитать profile и заблокировать адрес.

Если wallet не VALID, scoring-блок скрыт. Значение null не отображать как 0. ROI при null не показывать как обязательную метрику; в ЛК его строку можно скрыть. Тексты имени, причин и хэша выводить как текст с экранированием.

Пользователь не меняет registration_status, validation_status, uid_status или финансовые показатели через ЛК.

## Лидерборд

Публичный список: display_name, основной pnl и reward_tag; имеющиеся capital-поля и roi_percentage показываются только справочно. Порядок приходит с сервера: PNL по убыванию, отсутствие результата в конце. ROI не управляет порядком. Для null показывать «—», не 0. Если ROI отсутствует у всех строк, справочную колонку можно скрыть. При пустом массиве — «Нет допущенных участников».

Reward_tag показывать ровно как Special Partner Gift или RespectGift. UID, хэш вывода, Telegram ID и административные комментарии не выводить.

## Административный экран

Один список users с их данными, статусами wallet/rewards и scoring. Для регистрации — APPROVE/REJECT и обязательный admin_notes. Для wallet показывать адрес и хэш вывода; VALID/INVALID, при INVALID обязательная причина. В запрос wallet/validate передавать оба значения, которые админ действительно проверил.

Для PARTNER_GIFTS — VALID/INVALID UID. В запрос передавать проверенный exchange_uid. При WALLET_CHANGED/UID_CHANGED перечитать данные, не повторять автоматически решение для новой пары адрес/хэш или нового UID.

Для списка допуска — загрузка CSV по исходному маппингу. Для scoring — строки с обязательными tg_id и pnl; ROI и три capital-поля необязательны. Показать администратору, что отсутствующие справочные поля заменят прежние значения на null. При ошибке показывать номер строки и поле; никакая часть ошибочной загрузки не применяется.

Исключение смены кошелька не оформлять как обычную кнопку в админке; закрытый технический порядок указан в ALG-11.

## Матрица доступа

| Действие | Посетитель | Участник | Администратор |
| --- | --- | --- | --- |
| Register/login/polling | Да | Да | Да |
| Публичный leaderboard | Да | Да | Да |
| Собственный profile | Нет | Да | Да |
| Собственный wallet/rewards | Нет | Да | Да |
| Просмотр всех users | Нет | Нет | Да |
| Модерация регистрации/wallet/UID | Нет | Нет | Да |
| Импорт initial_users/scoring | Нет | Нет | Да |
| bot/verify | Нет | Нет | Нет; только сервис бота |

Права проверяет сервер. Скрытая кнопка в интерфейсе не является проверкой доступа. Администратор не передаёт свой статус как поле запроса.
