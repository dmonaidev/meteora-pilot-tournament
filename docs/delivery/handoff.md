# Передача готового проекта через GitHub

Владелец поручил: взять разработанное решение, сначала развернуть целиком, затем исправить фронтенд без изменения сценариев, алгоритмов и базы. Основное поручение — [CLAUDE_DEPLOY.md](../../CLAUDE_DEPLOY.md), подробный запуск — [server-transfer.md](server-transfer.md).

## Два репозитория

- PUBLIC: https://github.com/dmonaidev/meteora-pilot-tournament — код, полный фронтенд, сервер, бот, миграции 001–010, тесты, Docker/Compose, спецификации, описание экранов и публичные сохранённые настройки.
- PRIVATE: https://github.com/dmonaidev/meteora-pilot-tournament-transfer — полная база, готовый config/deploy.env с действующим BOT_TOKEN и административными ID, исходная локальная конфигурация, реестр XLSX, 22 снимка экранов и manifest SHA256.

Нужен доступ принимающего агента к PRIVATE через GitHub владельца. Архивы, токен и настройки вручную передавать не требуется. SSH-ключ отсутствует в комплекте: агент проверяет доступный доступ или запрашивает его у владельца.

## Перенос данных

Приватный data/application-data.json содержит правила и настройки, 3 профиля, 571 запись реестра, 2 кошелька, 2 записи UID/наград и 1 результат. Сохраняются UUID правил, даты UTC, имя турнира, ссылка партнёра, согласия, статусы допуска и ручных проверок, ведущие нули UID. Активные сессии и одноразовые коды не переносятся; участники входят заново.

Приватный config/deploy.env уже подготовлен для новой среды: новые различные секреты JWT/BOT_API и новый пароль БД, текущий токен бота/административные ID и production URL. Исходный config/local-source.env нужен только для сверки. Приватные файлы не включать в публичный Git, образ Docker, Releases или отчёты.

Импорт выполняется scripts/handoff.mjs restore FILE --fresh-database в новую пустую прикладную БД, до запуска app и без демозаполнения. Он применяет миграции, проверяет фиксированный состав и записывает строки транзакционно. Полный snapshot включает публичные настройки: два варианта импорта подряд не запускать. При непустой БД автоматическое удаление запрещено. Подробные команды в server-transfer.md и приватном README.

## Порядок работы агента

1. Прочитать AGENTS.md, Agent.md и CLAUDE_DEPLOY.md, скачать оба репозитория и записать SHA.
2. Проверить SSH/инфраструктуру, скопировать готовый config/deploy.env, собрать существующий проект, восстановить snapshot и развернуть HTTPS.
3. Остановить предыдущий polling перед запуском серверного бота; один процесс на токен.
4. Проверить готовое решение и сохранность данных.
5. Исправить фронтенд существующих компонентов по описанию экранов и снимкам, сохраняя поведение/алгоритмы/контракты/базу. Для их изменения нужно отдельное явное разрешение пользователя.
6. Собрать UI, проверить 1440px/390px и существующие сценарии на изолированной БД; передать отчёт и команды эксплуатации.

## Повторный экспорт и проверки

```sh
node scripts/handoff.mjs export .local/handoff
```

Экспорт читает согласованный snapshot и не меняет рабочую БД. Приватный результат может публиковаться только в одобренной PRIVATE репозитории, публичный JSON отдельно. После упаковки функционального кода прошли 89 серверных тестов; предыдущий полный браузерный прогон — 11 сценариев. См. docs/review/handoff-validation.md и docs/review/local-validation-v1.3.md. Проверки переноса выполнялись на временных БД.

## Уточнение владельца: разрешение и риск изменений

Запрещено самовольно менять алгоритмы, пользовательские сценарии, маппинг переменных между UI/API/ботом/БД, API-контракты, структуру БД и существующие записи. Сохранять имена полей, соответствия, типы, enum/null, единицы измерения и ведущие нули UID. Фронтенд менять только с явного разрешения пользователя в рамках согласованной правки. Развёртывание само по себе не разрешает менять фронтенд; разрешение менять фронтенд не разрешает менять защищённые части.

Если запрошенная пользователем правка может нарушить работу приложения, сценарии, алгоритмы, маппинг переменных, API или данные, до реализации предупредить пользователя: описать конкретные последствия и затронутые части, предложить безопасный вариант, запросить отдельное явное разрешение и дождаться ответа. Сам факт запроса правки и общее разрешение менять фронтенд не заменяют согласия на эти последствия.

Обязательные инструкции Claude: [../../CLAUDE.md](../../CLAUDE.md). Это уточнение владельца имеет приоритет над прежними общими формулировками разрешения исправлять UI.
