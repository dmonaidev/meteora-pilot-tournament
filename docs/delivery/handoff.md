# Передача проекта и сохранённых данных

Этот пакет передаёт локально проверенную версию 1.3. Публикация GitHub не развёртывает приложение.

## Состав

- Публичная репозитория: исходники, миграции 001–010, тесты, Docker/Compose, спецификация и `handoff/public-settings.json` с фактически сохранёнными названием, расписанием UTC, ссылкой партнёра и всеми редакциями правил, включая архив и отметки удаления.
- Отдельный приватный архив: `application-data.json` с теми же настройками и правилами, участниками, реестром допуска, кошельками, UID, статусами проверок, согласиями и результатами; `runtime-settings.json` с несекретными параметрами бота и административного доступа.
- Секреты `.env`, токен бота, пароли PostgreSQL, JWT/BOT_API_SECRET, активные сессии и одноразовые коды не публикуются и не входят в перенос. Участники после переноса входят заново.

Приватный архив содержит персональные данные. Передать принимающему агенту закрытым каналом; не коммитить и не загружать в публичные GitHub Releases/Issues.

## Принимающему агенту

1. Прочитать `AGENTS.md`, `Agent.md`, `docs/README.md` и `docs/product/access-and-cabinet.md`. Приоритет имеют уточнения 0.3–1.3; исходный модельный документ содержит устаревшие предположения.
2. Установить Node.js 24 и PostgreSQL 17. Выполнить `npm ci` и `npm run build`.
3. Создать **пустую отдельную БД**. Заполнить `.env` по `.env.example`: `DATABASE_URL`, новые различные случайные JWT_SECRET/BOT_API_SECRET минимум по 32 байта, BOT_USERNAME, ADMIN_TG_IDS, публичный HTTPS URL и **LOCAL_DEMO=false**. Токен Telegram получить у владельца по закрытому каналу. Локальные Windows-пути не переносить. Не запускать демонстрационный bootstrap перед восстановлением.
4. Выбрать **один** вариант восстановления:

```sh
# Только публичные настройки, без профилей и реестра:
node scripts/handoff.mjs restore handoff/public-settings.json --fresh-database

# ИЛИ настройки вместе с участниками из приватного архива:
node scripts/handoff.mjs restore /secure/application-data.json --fresh-database
```

Импорт применяет миграции, отказывается от непустой прикладной БД и записывает данные в одной транзакции. Нельзя запускать два варианта подряд в одной БД. Восстанавливаются абсолютные даты UTC и исходные ID редакций правил; номера редакций продолжаются после максимального сохранённого номера. Сохранённый статус DRAFT/ACTIVE/ARCHIVED не меняется: черновики не публикуются автоматически.

5. Если нужен Docker, использовать `deploy/README.md`. После запуска только `db app` применить импорт из контейнера приложения или утилитой Node с доступом к этой же пустой БД **до регистрации пользователей**. Пустая строка настроек, созданная миграциями, допускается. Перед импортом остановить app, затем восстановить через `docker compose --env-file deploy/.env -f deploy/compose.yml run --rm --no-deps app node scripts/handoff.mjs restore handoff/public-settings.json --fresh-database`. Для приватного файла примонтировать его read-only в отдельный разовый контейнер; не добавлять его в образ.
6. Проверить `/health`, настройки, название, UTC, публичный лидерборд, опубликованные правила, вход администратора и участника. При публичном варианте профили и реестр отсутствуют — импортировать их отдельно через админку либо выбрать полный приватный перенос вместо публичного.
7. Запуск бота согласовать с владельцем: один polling-процесс на токен. Рабочий локальный бот не останавливался при упаковке; два экземпляра одновременно конфликтуют. Существующий webhook не удалять автоматически.

Секреты генерируются заново, административные Telegram ID и имя бота берутся из приватного `runtime-settings.json`. Новый PUBLIC_BASE_URL/BACKEND_URL задаются для новой среды. Название, даты, ссылка партнёра, правила, статусы профилей и результаты уже в данных переноса; не заменять их демонстрационными значениями.

## Повторная упаковка

```sh
node scripts/handoff.mjs export .local/handoff
```

Экспорт читает единый согласованный snapshot БД и не изменяет её. Результаты приватного экспорта находятся только в `.local/handoff/private/`; публичный JSON отдельно в `.local/handoff/public-settings.json`. Перед публикацией публичной репозитории проверить секреты и персональные сведения во всех добавляемых файлах.
