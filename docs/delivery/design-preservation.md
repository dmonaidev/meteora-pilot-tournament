# Исправление фронтенда готового решения

Поручение владельца: **сначала развернуть готовое решение, затем исправить фронтенд**, сохранив сценарии, алгоритмы, API, структуру БД и существующие данные. Исходная реализация находится в `web/src/`. Исправления отображения и вёрстки разрешены этим поручением; изменения сценариев и бизнес-логики требуют отдельного явного разрешения пользователя — владельца проекта.

## Источник внешнего вида

| Область | Готовые файлы |
| --- | --- |
| Приложение, главная, вход, регистрация, кабинет, лидерборд | web/src/main.jsx, web/src/style.css |
| Админка, плитки, карточки, таблицы, импорт | web/src/admin.jsx, web/src/admin-data.jsx, web/src/admin.css |
| Расписание, метрики, даты и время UTC | web/src/schedule.jsx, web/src/schedule.css, web/src/utc.js |
| Название турнира | web/src/tournament-name.jsx |
| Special Gift, рефссылка, дорожная карта и баннер | web/src/partner.jsx, web/src/partner.css, web/src/gift-banner.jsx |
| Правила, согласие, редактор и архив | web/src/rules.jsx, web/src/rules.css |
| Дубликаты и статусы полей | web/src/profile-availability.jsx |
| Сессия и продление через Telegram | web/src/session.js, web/src/session-control.jsx |

CSS содержит последовательные уточнения: действующее правило определяется каскадом. Нельзя считать первые старые объявления итоговой палитрой. Итоговый фон `#05090a`, текст `#eef4f2`, основной акцент `#00e99a`, приглушённый текст `#91aaa4`, линии `#12382c`; партнёрские блоки используют фиолетовый. Основной шрифт Manrope с fallback; технические подписи используют monospace. Существующие размеры и media queries — исходная база исправлений читаемости и адаптивности.

Бренд: крупное `METEORA $MET`, сохранённое название турнира (начально `PILOT TOURNAMENT`), затем `Liquidity Providers` и `by Meteora Plus Community`. Название берётся с сервера, его изменение в админке не меняет остальной бренд.

## Экраны и состояния

Карта — [экраны и доступ](../product/screens-and-access.md), точные поля/API/права — [спецификация 1.3](../product/access-and-cabinet.md). Сохранить главную, окна входа/регистрации/правил, лидерборд, кабинет с UID и без него, статусы допуска/проверок, дорожную карту, баннер сессии и восемь разделов админки.

Визуальные примеры: https://github.com/dmonaidev/meteora-pilot-tournament-transfer/tree/main/design/screenshots. Получены из текущей сборки на временной восстановленной БД; индекс описывает состояния. Открытая регистрация и конец сессии моделируются только в временной БД. Скриншоты не заменяют код и не требуют менять рабочие даты/статусы.

## Что сохранять

- Русские надписи, иерархию бренда, палитру, иконки и интервалы.
- На широком экране форму кабинета слева, статусы/дорожную карту справа; готовую вертикальную мобильную раскладку.
- Навигацию «Личный кабинет», «Лидерборд» и существующий административный пункт. Не возвращать кнопку перехода в лидерборд внутри самого лидерборда.
- Даты по стадии турнира, UTC и 24 часа, собственный выбор часов 00–23, подпись «24 часа · UTC».
- Галочку UID, условные поля UID/хэша, предупреждение об отказе от Special Gift и статусы под полями.
- Разделение технической проверки дубликатов и ручного VALID; номинацию по сохранённым данным.
- Открытие/закрытие окон, сохранение ввода при ошибках, защиту двойных запросов, состояния загрузки/ошибки/пустых данных.
- Немедленное переключение плиток админки и защиту от устаревших ответов.

## Приёмка

Собрать `npm run build` или Dockerfile. Проверить 1440px и 390px: бренд, главную, лидерборд, кабинет, регистрацию, правила и настройки. Горизонтального переполнения страницы нет; таблицы могут иметь свою прокрутку. Проверить CSS, JS, иконки и шрифт. При недоступном внешнем шрифте сохранить предусмотренный fallback и выяснить причину.

На первом этапе неполадки развёртывания исправлять в сборке, proxy и окружении. На втором — исправить UI, не меняя серверные/ботовые алгоритмы, API и базу. Проверки запускать на изолированном стенде; рабочие записи и даты не менять ради тестов. Исторические материалы `docs/source/` и модель 0.2.1 не отменяют текущую реализацию.
