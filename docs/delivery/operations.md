# Запуск и эксплуатация приложения

Локальный адрес http://127.0.0.1:3000; БД PostgreSQL 17 на 127.0.0.1:55432. Команда npm run dev запускает PostgreSQL, сборку frontend, backend и при заданном BOT_TOKEN — бота. npm run start запускает только backend/готовый frontend с уже доступной БД. npm run bot запускает только бота.

Постоянное хранилище локально .local/postgres; конфигурация .env. При повторном запуске демо не перезаписывает существующих пользователей. Внутренние секреты создаёт scripts/setup.mjs. Изменять их вручную без необходимости не требуется.

Миграция npm run db:migrate; backend также применяет идемпотентную первоначальную миграцию при старте под PostgreSQL advisory lock. Сейчас одна первоначальная схема; последующие изменения схемы должны добавлять явные миграции, а не полагаться на CREATE TABLE IF NOT EXISTS для изменения существующих колонок.

Повторная сборка npm run build. При изменении серверного кода перезапустить backend. PostgreSQL работает отдельным процессом, обслуживает один каталог проекта; чужие кластеры запускатор не останавливает. Остановка общего запускатора Ctrl+C останавливает принадлежащие ему дочерние процессы и локальную БД, не удаляя её файлов.

Для реального турнира: LOCAL_DEMO=false, случайные JWT_SECRET и BOT_API_SECRET, настоящий BOT_USERNAME/BOT_TOKEN, оба проверенных Telegram ID в ADMIN_TG_IDS, фактический TOURNAMENT_START_AT. Не включать демонстрационный вход в production. Дата по текущей спецификации задаётся конфигурацией; публичной кнопки смены даты нет.

Проверить health: GET /health возвращает status=ok только при доступной БД. Локальные сообщения сервера идут в окно процесса; если запуск выполнен скрыто для текущего просмотра — .local/app.log и .local/app-error.log. PostgreSQL пишет .local/postgres.log. Значения секретов не выводить при диагностике.

Производственное развёртывание, обновления и DNS/TLS — [deploy/README.md](../../deploy/README.md) и [правила сервера](deployment.md). Docker-сборка исключает .local и .env. Образы backend и бота работают пользователем node; PostgreSQL имеет постоянный volume. Производственные бэкапы и откат требуют отдельного решения о сохранении новых данных; удаление старого проекта не даёт способа его восстановить.
