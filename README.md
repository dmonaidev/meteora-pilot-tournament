# METEORA $MET · PILOT TOURNAMENT

Локальный монолит: русский тёмный frontend, Fastify backend, PostgreSQL и Telegram-бот. Действующая спецификация — [документация](docs/README.md), доступ и ЛК — [версия 1.3](docs/product/access-and-cabinet.md).

## Посмотреть

Откройте http://127.0.0.1:3000/ на этом компьютере. Публичный лидерборд, показатели и опубликованные правила доступны гостю. Вход — Telegram username с @ или без @ либо числовой ID → одноразовый код в боте → ввод на сайте. Бот: **@lptournamentsupport_bot**; при первом входе откройте его на телефоне и отправьте /start. Код живёт 5 минут, повторная выдача — через 90 секунд.

Администратору открывается админка, участнику — свой ЛК. Права назначаются сервером по ADMIN_TG_IDS. В текущей локальной базе сохранены два реальных аккаунта и одна обозначенная демонстрационная запись. Переключатель синтетических аккаунтов выключен.

Сессия длится 30 минут и сохраняется между страницами, обновлениями и вкладками. В последние 5 минут можно запросить продолжение и подтвердить его кнопкой в Telegram; без подтверждения нужен новый вход по коду.

## Правила и регистрация

Админка → **Правила** → выбрать черновик → исправить текст → **Сохранить черновик** → **Опубликовать правила**. Можно загрузить .txt/.md. Приложенные draft-2026-10-01 правила импортированы только как черновик. Пока опубликованной версии нет, новая регистрация недоступна; вход существующих аккаунтов работает.

Новая регистрация требует галочки согласия с конкретной опубликованной редакцией. Новая публикация архивирует прежнюю. Действующий и архивный текст неизменяемы, доступны для публичного чтения; архив удаляется только явным подтверждённым действием администратора.

Расписание первоначально без дат, задаётся в админке. Ввод и отображение времени на платформе — UTC, поля даты и времени имеют кнопки календаря/часов. Наступившие сохранённые даты нельзя менять обычным действием. Начало турнира блокирует смену существующего кошелька. PNL, капитал, необязательный ROI и отдельный накопленный оборот открытий LP загружает администратор.

Реферальная ссылка: **Админка → Настройки турнира → Ссылка партнёра → Сохранить ссылку**. Единый URL используется в баннере и ЛК. Квалификацию Special Gift подтверждает администратор вручную после проверки UID и условий партнёра; кабинет показывает дорожную карту и сохранённый статус заявки.

Название: **Админка → Настройки турнира → Название турнира → Сохранить название**. Текущее PILOT TOURNAMENT можно заменить; бренд и лидерборд используют сохранённое значение. Время вводится в24часовом формате, под каждым полем — «24 часа · UTC».

## Повторный запуск

Нужен Node.js 24. В папке проекта:

~~~sh
npm ci
npm run dev
~~~

На этом компьютере можно открыть START_LOCAL.cmd. Запуск поднимает отдельную PostgreSQL на 127.0.0.1:55432, собирает UI и запускает приложение на 127.0.0.1:3000. Секреты находятся в .env, данные БД — .local/postgres. Не удаляйте каталог базы, если нужны введённые данные. Занятые чужими процессами порты автоматически не освобождаются.

BOT_TOKEN, BOT_USERNAME, ADMIN_TG_IDS и остальные настройки задаются в .env. Один токен обслуживается одним polling-процессом. Отдельный бот запускается командой npm run bot. Нажатие /start не назначает административные права.

## Проверки

~~~sh
npm test
npm run test:browser
~~~

Тесты используют отдельные временные базы и тестовый транспорт Telegram, не меняют рабочие профили и не отправляют реальные уведомления. Для браузерного стенда на новом компьютере установите Chromium: npx playwright install chromium. Итоги — [локальный прогон 1.3](docs/review/local-validation-v1.3.md).

## Перенос

Для передачи через GitHub см. [инструкцию принимающему агенту](docs/delivery/handoff.md). `handoff/public-settings.json` содержит текущие название, расписание UTC, ссылку партнёра и правила. Участники, реестр, готовая production-конфигурация и исходные секреты находятся в PRIVATE репозитории передачи; активные сессии и одноразовые коды не переносятся. Импорт выполняется `node scripts/handoff.mjs restore FILE --fresh-database` только в пустую прикладную БД.

Подготовлены [Compose, Dockerfile и proxy](deploy/README.md). Полный JSON snapshot восстанавливается штатным scripts/handoff.mjs; Windows-каталог PostgreSQL не копировать на Ubuntu. После развёртывания исправлять фронтенд существующего приложения в [установленных границах](docs/delivery/design-preservation.md). Сценарии, алгоритмы, API, структуру БД и данные менять только с отдельного явного разрешения владельца.
